# Media Naming Compressor v0.9

一个部署在 GitHub Pages 上的免费浏览器工具，用于批量读取视频信息、生成统一文件名并压制为 MP4。视频只在当前浏览器内处理，不会上传到服务器。

## 命名规则

```text
YYMMDD_P-{产品}_H-{主题}[H重复时-01/-02...]_VL-{S/M/L}-{时长}_S-{尺寸}_L-{语言}_D-{制作人}_M-{制作时长}.mp4
```

时长按自动读取并四舍五入的秒数分档：0–10s 使用 `VL-S-xx`，11–20s 使用 `VL-M-xx`，21–30s 使用 `VL-L-xx`，其中 `xx` 为秒数（例如 `VL-M-15`）。超过 30s 的素材也归为 L。

同一批素材只有 H 字段相同时才追加两位序号。删除素材后，剩余同主题素材会按当前顺序重新编号。
主题只保留文字和数字，每个单词首字母自动大写，并删除空格、标点和符号，例如 `brain training` → `BrainTraining`。重复主题输出为 `H-BrainTraining-01`，横线仅用于 H 前缀和自动序号；不重复时为 `H-BrainTraining`。

## 功能

- 批量添加视频并自动读取时长、分辨率和画幅比例。
- 从文件名 `L-en` 等标签识别语言，也可以手动覆盖。
- 主题 H 支持使用 Chrome 浏览器内置模型进行中英互译。
- 默认使用 MediaBunny/WebCodecs 压制 H.264 MP4，优先调用浏览器原生硬件编解码能力。
- WebCodecs 或素材编码不兼容时，单个文件自动回退到 FFmpeg WebAssembly，不影响同批其他文件使用极速引擎。
- AAC 源音轨在允许时直接复制，减少重复编码时间和音质损失。
- 可以仅压制并保留源文件主文件名，也可以按命名规则重命名后压制。
- “仅导出”按当前命名规则导出原视频，保留原格式、画质和音轨，不做压制；支持单个下载和 ZIP 批量下载。尚未合成的字幕需先完成字幕导出，或使用“批量命名并压制”。
- 提供广告标准、高质量和小体积三种压制预设，并在结果中标记实际使用的引擎。
- 支持单个下载和 ZIP 批量下载。
- ZIP 压缩包按 `日期-产品-制作人.zip` 命名。
- 站内独立的「自动字幕」页面（`#subtitles`）：一次选择或拖入多个视频，加入视频队列并逐个识别语音。批量识别按队列顺序运行，在浏览器内使用 Whisper 的词级时间戳生成短字幕；分段优先参考句末、逗号和气口，时长超限时避免拆开常见英文短语，常见缩写不会误判为句末。中文长词块优先在标点后切分。字幕按校准后首词和末词的时间出现及结束，停顿时隐藏，相邻字幕直接硬切。
- 每个视频独立保存字幕文本和样式；切换队列中的视频即可播放预览、按时间定位和校对字幕。三种样式以实际文字效果展示。
- 自动字幕默认快速识别，口播语言默认英语。英语使用同级别的 Tiny.en 英文专用模型，其他语言使用多语言 Tiny 并明确指定语言；Base 精准识别可按需选择。口播语言支持英语、中文、日语、韩语、西班牙语、法语、德语和葡萄牙语；没有伪装成自动语言检测。模型说明随模式和语言切换，说明速度、能力和局限；切换模型会释放上一个模型。分段保留 5 秒重叠上下文，执行所选语言转写。音频直接提取为 16 kHz 单声道 PCM，保留音轨片头延迟和时间戳空隙，避免字幕整体提前；识别时间限制在当前音频范围内，缺失时间戳与相同/倒退的词起点保留文字顺序。
- 使用随站点提供的 Silero VAD 检查语音和停顿边界；每个视频独立初始化检测状态。边界保留 160 毫秒余量以容纳弱声和辅音，按词在语句中的位置修剪跨越静音的起止时间，覆盖片头、片中和片尾。分段器不再凭词时长猜测结束时间，持续发声的长词不会被提前截断。VAD 只能辨别人声区间，不能识别词义，音乐人声、笑声或重叠语音仍可能造成误差。
- 20/40 毫秒等正常短词不因时长短而触发补充识别。与相邻词同一时间点的零时长词会合并到可靠锚点，保留全部文字；孤立零时长、倒退、缺失或异常长的时间仍需校准。压缩到句尾的短词只向独立检测到的语音起点扩展，不凭连续语音内的词间空隙猜起点。同一语音区域内的极短末词可与前文合并显示，避免闪一下就消失；检测到停顿时保留分段。数字、金额、小数、百分比、缩写连接和收尾标点在字幕分段与画面换行中保留完整。
- 剩余的时间异常使用当前选择的同一识别模型做有前后文的局部补充识别，每个视频最多 3 个窗口、每个不超过 20 秒；不会为校准自动切换更大模型。只采用前后文字上下文一致且不歧义的边界，保留主转写的口播文字；失败或无可靠匹配时显示「时间需校对」。正常词不增加 ASR 推理轮次。自动识别生成的方括号声音标注、音乐符号以及音乐/掌声/笑声等括号标注会过滤，支持拆成多个词块或混在口播中的标注；预览和导出使用同一份过滤后字幕。检测模型加载失败时仍可转写，但会提示校对。
- 字体提供默认无衬线、衬线、等宽，以及微软雅黑、黑体、宋体、楷体、仿宋、苹方、Arial、Helvetica、Verdana、Times New Roman、Georgia、Impact、Consolas，共 16 个选项。使用本机字体，缺失时按字体族回退；预览与两种导出引擎共用同一字体配置。
- 首次打开一个新版本时弹窗介绍功能，关闭后同版本不再自动弹出，可从右上角「更新说明」重看。打开页面、回到前台、网络恢复及每分钟检查部署版本；发现更新后，空闲页面在弹窗内倒计时 15 秒自动刷新。有视频、字幕或导出结果时停止自动刷新，用户下载保存后可主动刷新；处理任务进行中禁用刷新按钮。「稍后更新」取消当次倒计时，同一更新不反复弹窗。后台页面不自动刷新，缓存未更新时不会循环刷新。
- 可单独烧录并导出 MP4，或将所有已有字幕的视频批量烧录并打包为 ZIP。优先使用 MediaBunny/WebCodecs 逐帧叠加字幕，字幕图层仅在文字变化时重绘，AAC 源音轨直接复制；不支持的素材自动回退到 FFmpeg。
- 「发送到命名」立即移交原视频和独立的字幕/样式快照，不再等待整段视频烧录。导出时按所选预设一次完成字幕合成与压制，「仅压制」也会烧录字幕；成功后再次命名可直接使用成品。发送后在字幕页继续编辑，不会改变已发送的快照，需要重新发送才会采用新修改。
- FFmpeg 兼容路径保持字幕图片到下一个字幕或透明空白帧，保留完整显示区间；图片时间精度为毫秒，停顿和片尾不残留上一条字幕。字幕全部超出视频时长时会报错，防止导出看似成功但没有字幕的文件。
- 视频编码、FFmpeg 读写和语音推理按任务排队；支持 Web Locks 的浏览器会协调同一浏览器、同一站点的多个窗口，避免同时争抢编码器和大量内存。等待期间会显示任务提示，字幕移交无需排队。不同浏览器或不同浏览器配置文件的窗口无法共享这把锁。
- 常用字段历史只保存在当前浏览器的 `localStorage`。下拉列表中每条历史旁的 ❌ 可直接删除，刷新后仍保持删除。
- 上传符合命名规则的视频时，自动识别原日期、产品、主题、语言、制作人和制作时长（兼容旧版 `VL-秒数`）。同一批中不同的原命名按各素材保留，编辑上方字段可统一覆盖；时长和尺寸仍读取实际视频，主题重复序号按当前批次重新计算。

字幕规则参考：[Whisper 的词级时间戳与行宽/行数约束](https://github.com/openai/whisper/blob/main/whisper/utils.py)、[Subtitle Edit 的长行拆分与均衡](https://github.com/SubtitleEdit/subtitleedit/blob/main/docs/features/split-break-long-lines.md)、[subcap 的句界/时长/换行处理](https://github.com/bighippoman/subcap)。本项目保留短视频字幕的 2.3 秒时长上限，并按画布实际文字宽度换行。

对齐方案对比：[stable-ts](https://github.com/jianfch/stable-ts) 使用静音抑制与按停顿重新分组；[faster-whisper](https://github.com/SYSTRAN/faster-whisper) 集成 Silero VAD；[WhisperX](https://github.com/m-bain/whisperX) 将识别与语言对应的音素强制对齐模型分开。本项目结合前两者的语音边界检查思路，在浏览器内保留轻量识别和有上限的局部校准，未实现 WhisperX 的音素强制对齐，不能宣称与其精度相同。生产逻辑只依赖音频、时间戳和文字上下文，不读取文件名、特定台词或案例专属秒数。

英文专用模型的选择参考 [Whisper 官方模型说明](https://github.com/openai/whisper#available-models-and-languages)：英文应用中，tiny.en / base.en 通常优于同级别多语言模型。本项目保留轻量级模型，实际速度仍依设备和音频而变；切换语言和模型不等于能够保证所有错词自动纠正。

## 免费方案边界

- 网站托管在 GitHub Pages，不需要 Railway 或常驻服务器。
- 媒体不离开用户电脑，不产生服务器存储和流量账单。
- 中英互译不调用付费接口；需要最新版 Chrome 及其本地翻译模型，Safari 暂不支持该功能。
- Mac 和 Windows 均按浏览器与素材的实际编解码能力选择引擎。Safari 不再被固定排除在 WebCodecs 路径外；支持当前素材的 H.264 编码和解码时启用极速路径，否则自动使用 FFmpeg 兼容引擎。字幕字体同时包含 macOS 和 Windows 的系统字体回退。
- 压制速度、可处理文件大小仍受浏览器内存、素材编码和电脑性能限制。大型或长视频建议使用桌面版 FFmpeg。
- 自动字幕首次使用会从 Hugging Face 下载 Whisper 模型。模型推理及视频处理在本地进行；短视频更适合浏览器处理。字幕识别结果可能有误，导出前可在文本框中校对。
- GitHub Pages 公开站点适用于静态页面，不提供账号、云端历史或服务端任务队列。

## 本地开发

需要 Node.js 20.19 或更高版本。

```bash
npm install
npm run dev
```

构建并检查：

```bash
npm run check
npm run build
```

`npm run check` 包含字幕快照、逐帧时间选择、越界时间与任务排队等回归检查。实际浏览器导出回归可在安装 Playwright 与 Chrome 后运行（先启动开发服务器）：

```bash
node scripts/test-caption-export.mjs
node scripts/test-caption-recognition.mjs
node scripts/test-app-updates.mjs
```

也可设置 `PLAYWRIGHT_MODULE` 指向已有 Playwright 的 `index.mjs`，通过 `TEST_BROWSER_CHANNEL` 指定浏览器通道，`TEST_BASE_URL` 指定开发服务器。导出回归生成带 AAC 音轨的黑色视频，检查发送阶段不加载 FFmpeg、跨窗口排队、命名导出与仅压制、两种引擎导出的每帧字幕和停顿、音轨及完整时长。识别回归使用真实 FFmpeg，批量测试 44.1/48 kHz 音频及不同音轨延迟、字幕归属、异常时间戳、字体设置保留与模型释放；语音推理使用确定性替身，不下载模型，也不验证真实语音识别准确率。macOS Safari 实机仍需在 Mac 上验证，Windows 的浏览器测试不等同于 Mac 实机测试。

另有真实语音回归 `scripts/test-caption-real-asr.mjs`：传入本地视频路径，或设置 `CAPTION_FIXTURE_DIR` 遍历指定目录；先启动开发服务器。它实际提取音频并运行浏览器端 Silero VAD，再以 Node 原生运行时核对边界结果；快速模式和 Base 均实际执行转写。检查原转写的口播文字保留、声音标注过滤、时间不重叠且不超出音频范围、补充识别次数和长度有上限，无语音支持的区间需提示校对。`ASR_TEST_MODELS=tiny` 单独验证快速模式，`ASR_TEST_LANGUAGE` 指定口播语言（默认 en），`ASR_REPORT_PATH` 指定报告文件。首次运行下载识别模型到 `output/asr-model-cache`；视频、缓存与报告不提交。自动测试不等于人工逐词标注的精度评测。

完整浏览器回归 `node scripts/test-caption-browser-real.mjs <视频路径> ...` 使用原版缓存模型验证真实批量识别、视频归属、字幕合法时间、声音标注过滤、语言/模型说明以及移动端布局。先运行真实语音回归以准备模型缓存；可用 `TEST_BASE_URL` 指向生产构建的预览地址。报告写入 `output/caption-browser-real-report.json`，截图同目录；单次本机耗时不能当作模型的通用速度基准。

本次优化参考 [MediaBunny 的逐帧处理接口](https://github.com/Vanilagy/mediabunny/blob/main/src/conversion.ts)、[FFmpeg 的 framesync 参数](https://ffmpeg.org/ffmpeg-filters.html#Options-for-filters-with-several-inputs-_0028framesync_0029) 和 [LosslessCut 的多实例说明](https://github.com/mifi/lossless-cut/blob/master/docs/troubleshooting.md)。

`predev` 和 `prebuild` 会把 FFmpeg 回退引擎的 `@ffmpeg/core` 运行文件复制到 `public/ffmpeg/`。该目录和 `dist/` 都是生成产物，不提交到 Git。

每次发版需同步修改 `package.json` / `package-lock.json` 的版本与 `src/release-notes.js` 的功能说明。Vite 构建自动生成 `version.json`，与页面内置的构建标识一致；GitHub Actions 使用提交 SHA，本地构建使用唯一标识。首次部署更新检测功能后，已经打开的更早版本页面仍需手动刷新一次，后续版本才能自动检测。

## 隐私

源视频、字幕快照、压制结果和 ZIP 都只存在于当前页面的内存或浏览器下载中。关闭或刷新页面后，未下载的字幕任务和压制结果不会保留。多窗口排队只协调处理时机，不会在窗口之间共享或覆盖字幕。
